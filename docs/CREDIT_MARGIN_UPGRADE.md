# Credit profitability inventory and plan

Existing: automatic OpenRouter pricing, bounded token quotes, resolution/quantity/duration/audio pricing, admin cost overrides, feature policies, audited package/rule controls, provider usage records, atomic wallet reservation/settlement/release and idempotent job billing. Studio and Editor remain connected to the shared engine. Free chat and non-billable manual edits retain their existing policy.

Changes: all central calculation paths enforce minimum ceil(protected variable cost / 0.008), plus at least 50% margin at actual net revenue per credit. Higher configured markup, fees, expenses and feature margins can increase the quote; the minimum is not a guaranteed fixed price. Legacy verified rule-based paid quotes now use the same calculation. Unknown-cost paid paths fail closed instead of using arbitrary fallback credits. Creator default becomes 5000 credits / 80 USD, preserving custom packages and auditing the one-time migration from the unchanged 90 USD default. Historical approvals and deductions are not repriced.

Admin already manages packages, generation rules, model bindings, provider costs/overrides, policy margins, wallet adjustments, job history, usage and revenue reports. No new wallet, pricing engine or payment integration is introduced. Unsupported/unverified transcription or multimodal billing remains disabled pending a verified bounded cost; it is not assigned a fabricated price.

Plan: test exact margin floor, fees/overhead, discount package safety, low admin margins, quantity effects, price policy updates versus frozen approvals, idempotency and wallet concurrency. Use mocked providers only. Live MongoDB package values and payment settlement remain unverified until deployment.

Verification completed: backend build and frontend TypeScript check passed. 26 focused tests passed: 12 profitability/feature-cost cases, package migration and custom prices, legacy rule parity, invalid purchases, concurrent reservations, idempotent refunds, frozen approved terms, approval recovery, model re-quotes and provider-capacity safeguards. Feature-named arithmetic tests verify the common calculator, not new translation/transcription provider implementations. No live paid generation or payments were performed. Existing 3x markup is preserved where configured; the requested 50% margin and 0.008 formula are mandatory floors, not automatic reductions of higher admin rates.
